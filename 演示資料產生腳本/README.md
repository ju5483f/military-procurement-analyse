# 演示用管制表產生腳本

產生 `執行中軍購案個案管制表(演示用).xlsx`（451 筆虛構資料），用於**公開區向同事演示** v1150715 的操作流程。

## 為什麼需要這些腳本

演示檔不是隨機亂數——它必須滿足一個硬性條件：

> 以 v1150715 分析後，20 項控制點 ×（陸/海/空/其他/合計/第二階段）**共 120 格數字，
> 必須與機密區真實實測結果 `分析結果0716.xlsx` 完全相同。**

這是一個約束求解問題，靠手工湊不出來，故以退火演算法求解。

## 執行順序

需要 Node，且同目錄要有 `xlsx.full.min.js`（可從 v1150715.html 內嵌的 SheetJS 抽出）。

```bash
node feasibility.js      # 1. 檢查目標矩陣是否可解（會列出緊繃約束）
node gen_demo.js         # 2. 退火求解 → demo_cases.json（誤差須為 0）
node jitter.js           # 3. 金額加抖動使數字自然（嚴格保持命中集合不變）
node build_demo_xlsx.js  # 4. 指派案號/單位/案名 → 產出 xlsx
node compare.js          # 5. 逐格比對（需先貼上系統實跑結果）
```

`gen_demo.js` 為隨機演算法，每次結果不同但都會收斂到誤差 0。若卡住不收斂，重跑即可。

## 關鍵設計

**數學關係**（推導自控制點定義，是求解的基礎）：

- 令 `H`=發價值、`J`=結匯率、`L`=交運率、`OI`=FRB占比，則
  `I = J·H`、`K = L·I`、`M = I−K`、`O = OI·I`
- **`diff = |K/H − J| = J(1−L) = M/H`** — 1-3/1-4 與 1-2、1-10 因此互相耦合
- 軍投 1-10（`J≥0.9 且 L<0.5`）→ `diff ≥ 0.45 ≥ 0.4` → **必然連帶命中 1-3**
- 1-5/2-5 對 `L=0` 的案件永遠滿足第一條件，只能靠 `I−O` 金額門檻擋掉

**第二階段**：只有案號出現在 `會議資料/` 的案件會命中。會議檔僅陸軍、海軍，
故空軍與其他軍種的第二階段恆為 0——目標矩陣恰好符合此限制（見 feasibility.js）。
實際需要真實案號：陸軍 21 筆、海軍 9 筆（可用 51/37）。

**兩個緊繃約束**：1-8 與 1-10 的第二階段命中數 = 陸+海案件數，
代表這些案件的案號必須 100% 取自會議檔，沒有容錯空間。

## 資料性質

- 金額、案名、單位、項次：**全部虛構**
- 案號：命中會議檔的 30 筆沿用 `會議資料/` 之真實案號與案名（該資料屬公開）；
  其餘 421 筆為虛構案號（已確保不與會議檔重複）
- 類別欄含少量「特別預算」，用以演示其併入軍投類分析的行為
